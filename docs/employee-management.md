# Employee Management

Phase 4 implements employee administration and linked user account creation.

## Fields

Employees store employee number, linked user, department, personal information, contact/address information, position, employment type, employment status, hire date, professional license data, doctor-specific fields, work schedule notes, profile photo path, emergency contact, creator/updater references, timestamps, and soft deletes.

Age is not stored; it is calculated from date of birth.

## Employee Number

Employee numbers use:

```text
EMP-YYYY-000001
```

Numbers are generated by `App\Services\ReferenceNumberService` using a `reference_sequences` table and row locking inside a transaction. The `employees.employee_number` column has a unique constraint as a final collision guard.

## Account Creation

Administrative employee creation creates:

- User account
- Employee profile
- Primary employee role assignment
- Optional profile photo path
- Audit log record

The operation is transactional. If database work fails after an upload, the newly uploaded file is cleaned up.

Allowed employee roles are `hospital-admin`, `doctor`, `nurse`, `pharmacist`, `laboratory-staff`, and `cashier`. Super Admin can also assign `super-admin`; Hospital Admin cannot. The `patient` role is never assignable to employee accounts.

## Profile Photos

Profile photos accept JPEG, PNG, and WebP files up to 2 MB. Files are stored under `employee-photos` on the public disk with randomized names. Executable files are rejected.

## Archive and Restore

Archiving soft-deletes the employee, marks employment inactive, removes the employee from any department-head assignment, and deactivates the linked user account. Restoring the employee does not automatically reactivate the user account.

## Own Profile

Staff can view their own profile at:

```text
/profile/employment
```

Patients cannot access employee management or employment profiles.
